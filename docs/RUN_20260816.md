## ① 안전검사 오차단 — 53건 (최우선)

### 증상

`IRP에서 살 수 있는 주식형 펀드 뭐 있어요?`, `요양 때문에 중도인출하려면 뭐가
필요해요?` 같은 **명백한 도메인 핵심 질문**이 1번 노드에서 잘렸다.
차단된 53건은 전부 `llm_calls = 1`, 경로가 `check_safety → out_of_scope` 다.

### 원인 — 보정 장치가 `res.safe` 뒤에 가려져 있다

`nodes/safety_checker.py` 의 구조가 이렇다.

```python
if res.safe and out_of_scope:        # ← 이 게이트가 문제
    fund = mentions_known_fund(question)      # 펀드명 대조 보정
    ...
    sig = corpus_signal(question)             # BM25 코퍼스 신호 보정
```

보정 두 개(펀드명 대조, 코퍼스 신호)는 **`res.safe == True` 일 때만 실행된다.**
모델이 `safe=false` 를 뱉는 순간 보정은 아예 돌지 않고 무조건 차단된다.

`요양 중도인출 서류` 는 BM25 신호가 40을 훌쩍 넘어(임계값 20) 보정이 살렸어야 하는데
차단됐다. 즉 이 건들은 `out_of_scope` 가 아니라 **`safe=false` 로 판정된 것**이다.

### 판정이 흔들린다는 증거

거의 같은 질문이 정반대 결과를 냈다.

| 질문 | 결과 |
|---|---|
| `미래에셋장기성장포커스 C-P 총보수가 얼마죠?` | 통과 |
| `미래에셋장기성장포커스 총보수 얼마예요?` | **차단** |
| `공무원도 IRP 가입할 수 있나요?` | 통과 |
| `군인연금 받는데 퇴직연금도 같이 가입되나요?` | **차단** |

같은 펀드, 같은 유형인데 갈린다. 경량 모델(HCX-DASH-002)의 판정이 안정적이지 않다.
`reason` 필드가 **78건 전부 빈 문자열**인 것도 같은 신호다 — 모델이 근거를 쓰지 않고
플래그만 찍고 있다.

토큰이 947~1,026(단일 호출 범위)이므로 JSON 파싱은 성공했다. 형식 문제가 아니라
**판정 내용의 문제**다.

### 자기 지적

지난 수정에서 안전 프롬프트에 "과잉 차단이 미탐보다 비싸다" 문단과 지시무시 대응
문단을 **추가**했다. 프롬프트가 길어지면서 경량 모델이 오히려 보수적으로 기울었을
가능성이 있다. 개편 전 수치가 없어 단정할 수는 없지만, 후보에서 배제하면 안 된다.

### 수정 방향

1. **보정을 `res.safe` 게이트 밖으로 뺀다.** 보유 펀드명이 명시된 질문이나 코퍼스
   신호가 임계값을 넘는 질문은 `safe=false` 라도 재검토한다.
   단, 진짜 차단해야 할 것(개인정보 요구·위법 조력)은 별도 축으로 분리해 유지한다.
2. **`reason` 이 비면 차단 판정을 신뢰하지 않는다.** 근거를 못 쓰는 판정은 근거가
   없는 판정이다.
3. **안전검사 모델을 격상**(`MODEL_PLAN` → `MODEL_ANSWER`)하고 비용을 잰다.
   1번 노드는 복구 경로가 없어서 여기서 아끼면 전체가 죽는다.
4. 안전 프롬프트를 개편 전으로 되돌린 A/B 를 한 번 돌린다.

## ② 구조화 출력 파싱 실패 — 6건

`llm_calls = 0` 으로 죽었다. 복구 호출까지 실패한 경우다.

| qid | 스키마 | 모델이 실제로 뱉은 것 |
|---|---|---|
| P-A5 · P-E1 · D-G3 | `GeneratedAnswer` | `main_answer` 를 **배열**로 반환 (`str` 이어야 함) |
| P-C3 | `QueryAnalysis` | `fund_name` 을 **문자열**로 반환 (`List[str]` 이어야 함) |
| P-A2 | `GeneratedAnswer` | JSON 없이 **마크다운 표**를 그대로 출력 |
| P-B2 | `GeneratedAnswer` | JSON 시작 후 중간에서 끊김 |

### 원인 — 프롬프트와 스키마가 서로 다른 것을 요구한다

`answer_recommend_system` 은 **"상품을 나열할 때는 표로 정리한다"** 고 지시한다.
모델은 표를 만들려다 `main_answer` 를 행 배열로 내놓거나 마크다운 표를 그대로 뱉는다.
6건 중 5건이 상품 트랙인 것이 우연이 아니다.

### 수정 방향

1. 스키마에 **관대한 변환기**를 붙인다. `main_answer` 가 리스트로 오면 줄바꿈으로
   합치고, `fund_name` 이 문자열로 오면 1원소 리스트로 감싼다
   (pydantic `field_validator(mode="before")`).
2. 프롬프트에 **"표는 `main_answer` 문자열 안에 마크다운으로 넣는다"** 를 명시한다.
   지금은 "표로 정리하라"만 있고 어디에 넣으라는 말이 없다.
3. 복구 호출이 실패하면 **답변을 통째로 버리지 말고** 원문을 `main_answer` 로 담아
   인용 없이라도 내보내는 최후 폴백을 둔다.

## ③ 레이트리밋 429 — 2건

`P-C2`, `P-C5` 가 `CLOVA HTTP 429: Too many requests` 로 죽었다.
로직 문제가 아니라 처리량 문제다.

`LLM_MAX_RETRY=3` 이 있지만 429 에 대한 **지수 백오프가 없다.**
호출이 558회 몰리면서 걸렸다.

수정: 429 응답에 한해 `Retry-After` 헤더를 읽고 대기, 없으면 지수 백오프.
문항 사이에 짧은 간격을 두는 옵션도 함께.
