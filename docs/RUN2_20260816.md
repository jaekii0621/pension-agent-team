## ① 인용 오배치 — 11건 (신규 발견, 최우선)

### 증상

`미래에셋장기성장포커스 C-P 총보수가 얼마죠?` 의 답은 **1.57%로 정확한데**,
출처가 `doc53`(ETF/TDF 안내 문서)으로 찍혀 있다. 그 문서에 이 펀드의 클래스별
보수가 있을 리 없다.

검색 결과를 보면 원인이 아니다 — **검색은 정상이었다.**

```
검색: 24건 → class_card 18, fund_card 2, doc/procedure 4
인용: doc53#p2#c008, doc53#p1#c011   ← 규정문서 2건만
```

같은 패턴이 11건. **검색이 상품 위주였는데 인용은 규정문서만** 나온 경우다.

| qid | 검색 분포 | 인용 |
|---|---|---|
| P-B2 · P-C1 · P-C3 · P-C4 · P-C5 · P-E2 · P-F5 | 상품 20 / 규정 4 | 규정만 1~3건 |
| P-B4 | 상품 20 / 규정 4 | 규정 3건 |
| P-E1 | 상품 37 / 규정 11 | 규정 3건 |
| P-E7 | 상품 43 / 규정 5 | 규정 1건 |
| D-G3 | 상품 22 / 규정 18 | 규정 4건 |

### 원인 — 두 가지가 겹쳤다

**(1) 근거 배치 순서가 인용 번호를 어긋나게 한다**

`nodes/answer_generator.py` 의 `_order_by_trust()` 는 규정문서를 **앞에** 놓는다.
"LLM 은 앞쪽 컨텍스트에 더 큰 가중을 둔다"는 이유로 넣은 장치다.

그런데 상품 질문에서는 검색 결과가 `규정 4 + 상품 20` 이므로, 배치하면

```
[1]~[4]   규정문서 (관련 없음)
[5]~[24]  클래스카드·펀드카드 (여기에 답이 있다)
```

모델은 답을 [7]쯤에서 읽고도 인용은 낮은 번호로 다는 경향이 있다.
**신뢰도를 심으려던 장치가 인용 정확도를 깨뜨리고 있다.**

**(2) 인용 누락 시 폴백이 항상 규정문서를 집는다**

```python
if not cites and res.evidence_sufficient:
    cites = [dict(to_citation(c), n=i + 1) for i, c in enumerate(ordered[:3])]
```

`ordered[:3]` 은 정렬 때문에 **언제나 규정문서 3건**이다. 상품 질문에서는
구조적으로 틀린 출처가 붙는다. P-B4 가 이 경로다 — 답변은 "확인할 수 없습니다"
인데 출처 3건이 붙어 있다.

### 수정 방향

1. **배치 순서를 질문 성격에 맞춘다.** `product_affinity` 가 높으면 상품 근거를
   앞에 둔다. 신뢰도 신호는 이미 근거 머리의 `출처=` 표시와 프롬프트 규칙으로
   이중으로 걸려 있으므로, 순서까지 동원할 필요가 없다.
2. **폴백을 '상위 3건'이 아니라 '답변에 실제로 쓰인 근거'로.** 최소한
   질문 성격에 맞는 계층에서 고른다. 답변이 "확인 불가"이면 인용을 붙이지 않는다.
3. 인용 번호가 유효 범위 밖이거나 계층이 어긋나면 **로그로 남긴다.** 지금은
   조용히 잘못된 출처가 나간다.
