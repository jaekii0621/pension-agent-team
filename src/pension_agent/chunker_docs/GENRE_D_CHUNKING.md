# 장르D(안전문서) 청킹 로직 정리

**대상**: doc55, doc6, doc35 (docx) + doc34 (xlsx) — 이미지 문제 없음 확정된 4개
**청킹 코드**: `build_chunks_genre_d.py`
**결과물**: `chunks_genre_d.jsonl` (141개 청크)

---

## 1. 청크 구조

| 문서 | 형식 | 총 청크 | paragraph | table_row |
|---|---|---|---|---|
| doc55 | docx | 102 | 66 | 36 |
| doc6 | docx | 11 | 8 | 3 |
| doc35 | docx | 2 | 2 | 0 |
| doc34 | xlsx | 26 | 0 | 26 |

- `ChunkD(Chunk)` — `origin`(문단/표행) + `file_type`(docx/xlsx) 필드 추가
- `source="절차"` 고정 (업무매뉴얼·코드표 성격)

---

## 2. docx 3개(doc55/6/35) — 장르B 로직 그대로 재사용

`parse_genre_d.py`(원본, 병합 미처리 버전) 대신, **장르B에서 이미 검증된 병합 인식 로직**(`get_real_row_cells`, `resolve_table_grid`)을 그대로 가져다 씀. 문단 헤딩 판단 규칙(`looks_like_heading`)은 doc55의 문서 구조(대분류 `1.`, 중분류 `가.`, 소분류 `1)`, 대괄호 제목 `[납입]`)에 맞춰 패턴을 추가:
- `[제목]` 형태 (대괄호로 감싼 한 줄)
- `가.`/`나.`/`다.` (중분류)
- `1)`/`2)` (소분류)

---

## 3. doc34(xlsx) — 코드표 전용 처리

실제 구조 확인 결과, 시트 전체(32행×11열)가 아니라 **B, C열 두 칸만 실사용**(나머지는 빈 칸). 헤더 행("불가사유코드", "불가사유")을 찾은 뒤, 그 아래 26개 행(01~25 + 99) 각각을 독립 청크로 변환. 장르C의 "행 완결성 원칙"과 동일한 방식.

```
[실물이전 불가사유 01. 소규모 펀드 임의해지] 가입자가 보유한 펀드가 소규모 펀드(잔고 50억 미만) 임의해지 대상 펀드에 해당 할 경우
```

## 4. 알려진 특이사항 (버그 아님)

- **doc55 첫 청크가 목차(TOC) 텍스트**: "퇴직연금 업무 시 도움되는 체크 포인트 ∙∙∙ 1 ..." 처럼 점선+페이지번호로 된 목차가 그대로 청크 하나로 들어감. 실제 내용이 아니라 안내용 목차라 검색 근거로서 가치는 낮지만, 굳이 걸러낼 필요는 없어 보여 그대로 둠(제거하고 싶으면 doc55 첫 청크만 수동 삭제하면 됨).
- **doc6#c001 표1**: "[업무매뉴얼] 퇴직연금 부담금 입금"이라는 제목 배너용 1칸짜리 표. 데이터 성격이 아니라 표지 역할이라 내용은 짧지만 그대로 둠.
- **길이 경고**: doc34의 코드 설명 대부분이 원래 한두 문장이라 300자 미만 경고가 많이 뜸(정상).
