## 1. 청크 구조

문단은 그룹핑해서 청크로, 표는 (특수 케이스 제외) 행 단위로 청크. 원본 문서의 문단↔표 순서를 그대로 따라감.

| 청크 종류(`origin` 필드) | 개수(전체) | 설명 |
|---|---|---|
| `paragraph` | 65개 | 문단 여러 개를 300~800자 기준으로 묶음 |
| `table_row` | 84개 | 표의 데이터 행 하나 = 청크 하나 |
| `calc_box_text` | 2개 | 계산식 강조박스(doc39, doc52 각 1개)를 문장으로 변환 |
| `flowchart_narrative` | 0개(별도 생성 안 함) | doc23 표2는 통째로 스킵, 이미 있는 서술 문단이 대신 청크됨 |

- `ChunkB(Chunk)` — `schema.py`의 `Chunk`를 상속, `origin` 필드만 추가(이 청크가 원본에서 어떤 형태였는지 추적용, 디버깅 목적)
- `source="세제"` 고정

## 2. 핵심 설계 — "병합 태그를 실제 값으로 되살리기"

지난번 `parse_genre_b.py` 수정으로 `[가로병합:2칸]`, `[세로병합 이어짐(윗셀과 동일값)]` 같은 태그가 붙게 됐는데, 청킹 코드에서는 이 태그를 **다시 실제 값으로 채워서 완전한 사각 그리드로 복원**함(`resolve_table_grid()`).

- 가로병합(`gridSpan`): 값을 병합된 칸 수만큼 반복
- 세로병합 이어짐(`vMerge continue`): 같은 열의 바로 위 "시작" 셀 값을 그대로 사용

복원된 그리드를 표 유형에 따라 다르게 처리:

| 표 유형 | 판단 기준 | 처리 방식 |
|---|---|---|
| 일반 표 | 기본값 | 헤더 행 기준으로 데이터 행마다 `"헤더: 값, 헤더: 값..."` 형태의 문장 생성 |
| 흐름도 (doc23 표2) | 미리 지정한 예외 목록 | 표 자체를 스킵. 원문에 이미 있는 서술 문단([문단28])이 순서상 그대로 청크가 됨 |
| 계산식 강조박스 (doc39 표1, doc52 표1) | 미리 지정한 예외 목록 | `-`(차감)/`=`(결과) 기호를 살려서 "A → (차감) B → (결과) C" 형태의 문장으로 변환 |

## 3. 문단 청킹 기준

- 문단을 순서대로 이어붙이다가, 다음 조건에서 새 청크로 끊음:
  - 누적 글자수가 800자를 넘으면 무조건 끊음
  - 누적 글자수가 300자를 넘긴 상태에서, 새 절 제목처럼 보이는 문단(`looks_like_heading()`)을 만나면 끊음
- "제목처럼 보이는 문단" 판단 기준: 20자 이하이면서 문장부호로 안 끝나거나, `①②③` 같은 원문자로 시작하거나, `1. 가나다` 처럼 숫자+한글로 시작

## 4. 알려진 특이사항 (버그 아님)

- **doc23 표3처럼 헤더가 "구분"으로 중복된 표**: 데이터 행에서 `"구분: 가입, 구분: 요건, ..."`처럼 헤더 라벨이 두 번 나옴. 원본 헤더 자체가 실제로 병합된 "구분" 한 칸이라 그런 것 — 코드가 지어낸 게 아니라 원본 구조를 정직하게 반영한 결과. 더 예쁘게 하려면 헤더 라벨을 수동으로 "대분류"/"소분류" 등으로 바꿔줘야 함(자동화하지 않음, 값 왜곡 위험).
- **길이 경고 대상 많음**: 특히 doc52(계산 구조 설명 표들)는 행 하나하나가 원래 짧아서(9~80자) 경고가 많이 뜸. schema.py는 경고만 하고 막지 않음.
