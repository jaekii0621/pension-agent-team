# 장르C 청킹 로직 정리

**대상**: 중도인출 5개 (doc46, 47, 48, 49, 50)
**입력**: `parse_genre_c.py` 결과(공통도입부/사유별 서두/표 데이터 분리 완료)
**청킹 코드**: `build_chunks_genre_c.py`
**결과물**: `chunks_genre_c.jsonl` (20개 청크)

---

## 1. 청크 구조

문서 하나당 **"개요" 청크 1개 + 세부서류 청크 여러 개**로 구성.

| 청크 종류 | 개수(전체) | 비고 |
|---|---|---|
| 개요(공통도입부+사유별 설명+신청양식) | 5개 (문서당 1개) | 300~800자 범위 안에 들어옴 |
| 세부서류 항목 (표의 각 행 = 1청크) | 15개 | doc49/50은 `하위유형` 필드로 세분화 |

- `ChunkC(Chunk)` — `schema.py`의 `Chunk`를 상속, `사유`(필수) / `하위유형`(선택) 필드 추가
- `사유`: "요양" / "파산개인회생" / "전세보증금" / "주택구입" / "재난피해"
- `하위유형`: doc49(주택매매/분양/조합/신축/경매공매), doc50(물적피해/인적피해)만 사용, 나머지는 None

### 개요 청크 예시 (doc46)
```
중도인출
· 퇴직연금제도는 사용자가 퇴직하는 근로자에게... (공통도입부)

근로자 본인 또는 배우자 등 부양가족의 6개월이상 요양이 필요한 경우
■ 신청기준: ... (사유별 서두설명)

[신청양식] DC.기업형IRP 중도인출신청서...
```

### 세부서류 청크 예시 (doc49, 하위유형 있는 경우)
```
[주택구입 중도인출 - 구입유형별 필수서류 - 주택매매]
주택 매매계약서 사본(가족간거래의 경우...)
```
→ `사유="주택구입"`, `하위유형="주택매매"`로 필터링 가능

## 2. 핵심 설계 결정

### "신청양식" 항목은 별도 청크로 안 만들고 개요에 합침
5개 문서 전부 "신청양식" 내용이 60~80자로 짧고 거의 동일(양식 이름만 있음) → 독립 청크로 두면 정보가 희박한 채로 검색에 걸릴 수 있어서, 개요 청크에 흡수시킴. 덕분에 개요 청크 길이도 300~800자 권장 범위에 자연스럽게 맞음.

### 표의 각 행 = 독립 청크 (row 완결성 원칙)
"각 행만 봐도 완결된 정보인가" 기준으로, 표 데이터를 통째로 하나의 청크에 넣지 않고 행(서류 항목) 단위로 쪼갬. doc49/50처럼 하위유형이 있는 경우, 사용자가 "주택신축 중도인출 서류가 뭐야?" 처럼 구체적으로 물었을 때 다른 하위유형과 섞이지 않고 정확히 매칭되게 하려는 목적.

---

## 3. 알려진 특이사항 (버그 아님)

- **세부서류 청크 상당수가 300자 미만** (예: "파산선고 증빙서류" 58자): 항목 자체가 원래 짧아서 그런 거라 억지로 늘리지 않음. schema.py는 경고만 하고 막지 않음.
- **공통도입부 중복 저장**: 5개 문서 각각의 개요 청크에 똑같은 공통도입부 문장이 매번 들어감(참조 방식 대신). RAG 검색 특성상 각 청크가 다른 청크 없이도 단독으로 이해 가능해야 하므로, 중복을 감수하고 넣는 쪽을 택함.

## 4. 다음에 참고할 것
